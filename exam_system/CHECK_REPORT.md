## 三、已知问题与Bug反馈
### 1. 安全隐患
- **硬编码敏感信息**：数据库密码、API密钥直接写在代码中
- **文件上传漏洞**：未严格限制上传文件类型和大小
- **会话安全**：使用localStorage存储会话ID，无HttpOnly/Secure标志
- **权限过高**：数据库使用root账号连接

### 2. 功能缺陷
- **多用户冲突**：全局变量`chat_sessions`/`quiz_state`导致多用户会话互相干扰
- **无分页机制**：列表接口无分页，数据量大时会卡顿
- **搜索功能不完善**：仅支持简单关键词匹配，无全文搜索
- **无用户认证**：所有接口无登录验证，任意用户可操作所有数据

### 3. 代码与性能问题
- **全局状态污染**：过多使用全局变量，难以维护
- **无缓存机制**：每次请求直接查询数据库，性能低下
- **后台进程脆弱**：`cet4_preload_daemon.py`无错误处理和重试机制
- **日志不规范**：使用print代替logging模块

### 4. 样式细节
- 部分响应式断点未覆盖，小屏幕适配仍有优化空间
- 暗色主题部分交互细节（如hover效果）未统一

## 四、优化建议
### 1. 安全加固
1. 使用`python-dotenv`加载环境变量，替换硬编码配置
2. 为Flask添加CSRF保护和会话安全机制
3. 限制上传文件类型和大小，使用更严格的安全校验
4. 创建专用数据库用户，避免使用root账号

### 2. 功能优化
1. 重构全局会话存储，使用Redis替代内存字典
2. 为所有列表接口添加分页支持
3. 集成全文搜索引擎（如Elasticsearch）优化搜索功能
4. 添加用户认证系统（如JWT）

### 3. 性能提升
1. 引入缓存机制（如Flask-Caching）减少数据库查询
2. 优化后台预加载进程，添加错误处理和重试逻辑
3. 降低系统状态接口刷新频率（建议5秒以上）

### 4. 代码规范
1. 提取配置到单独文件，统一管理
2. 标准化API响应格式
3. 添加单元测试和集成测试
4. 引入类型检查和代码格式化工具

### 5. 体验优化
1. 完善响应式设计，适配更多屏幕尺寸
2. 统一暗色主题交互细节
3. 集成Swagger文档方便API调试
4. 添加多语言支持
